# AAI6630 Phase 2 MolGlyph Recognition

Yihang Xu implements Stage 3 of the team's PDF-to-SMILES pipeline. This module accepts individually cropped molecule images with `crop_id`, `paper_id`, and `crop_path`, runs BioMiner's pretrained MolGlyph once per image, and passes decoded SMILES to the RDKit validation stage. It does not perform PDF parsing, molecule detection, reference matching, or final evaluation.

## Files

- `AAI6630_2.3_MolGlyph_Recognition_Portable.ipynb`: runnable module and documented example.
- `crops.csv`: four manually cropped XN paper 2 examples; image paths are relative to `outputs/phase2_recognition/crops.csv` in the project directory. The images themselves are generated by Assignment 1.2 and are not included here.
- `raw_predictions.csv`: actual output from the four-image MolGlyph run. All four rows have `recognition_status=ok`.

## Run

Place the notebook beside `BioMiner-main`, `molglyph_large.pt`, and `outputs` in the project directory. Generate the four XN images by running the crop cell in Assignment 1.2. Then run the notebook from the first cell. It writes `outputs/phase2_recognition/crops.csv` and `raw_predictions.csv`. To use detection-stage results, change `CROPS_CSV` in Section 1 to the detector manifest, skip Section 2, and run Sections 3–5. Relative `crop_path` values are resolved from the manifest's parent folder. Model and image files are not stored in this submission.

## Interface and methods

Required input columns: `crop_id`, `paper_id`, `crop_path`. The example also includes page and molecule label. Required output columns: `crop_id`, `paper_id`, `raw_smiles`, `inference_time` (seconds). Added fields retain `raw_caption`, `recognition_status`, and `error` so every input has a traceable output, including failures. `raw_smiles` is reconstructed with BioMiner's official `Translator.refactor` when the caption includes `<sep>`. The validation lead should confirm this definition before integration.

MolGlyph was chosen because it is the pretrained OCSR component benchmarked in Phase 1. The code loads it once on CPU and passes saved crop images directly to `predict_image_file`. It does not fine-tune the model or apply augmentation, resizing, or normalization beyond any operations inside BioMiner. Preprocessing is handled upstream by PDF parsing and molecule detection. The four saved examples are manual crops and provide a recognition smoke test, not evidence of automatic detection accuracy.
